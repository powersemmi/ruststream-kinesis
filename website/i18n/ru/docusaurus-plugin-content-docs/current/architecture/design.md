# Устройство

Где стоит `ruststream-kinesis`: между рантаймом RustStream и AWS SDK, по читателю на сегмент,
рядом хранилище аренд, один клиент SDK на рантайм.

<Diagram name="design" words={words} />

Крейт реализует трейты брокера из ядра поверх
[AWS SDK для Rust](https://docs.rs/aws-sdk-kinesis/latest/aws_sdk_kinesis/). Рантайм над ним один
для всех брокеров. Всё, что относится к Kinesis, лежит в этом крейте: дескриптор
[`KinesisStream`](api:ruststream_kinesis::KinesisStream), читатели сегментов, аренды, действие
исхода на контрольную точку и способ, которым запись хранит заголовки. Крейт подписывается,
принимает пакеты, перематывает подписку, передаёт ключ сегмента в диспетчеризацию по ключу
и описывает свой сервер в генерируемом документе. Транзакций и запросов с ответом у него нет.

Каждая подписка читает один поток. Задача-координатор перечисляет сегменты потока, берёт аренду
каждого сегмента, который может взять, и запускает по задаче-читателю на каждый удерживаемый
сегмент. Все читатели пишут в один канал на 64 доставки, а поток доставок подписки забирает их
оттуда. Подписка на пакеты группирует те же доставки на стороне клиента. Координатор и читатели
работают в рантайме, который подключил брокер.

Подключённый брокер и все издатели делят одно соединение: клиент SDK, хранилище аренд,
идентификатор владельца аренды и признак закрытия. SDK открывает HTTP-соединение в рантайме того
запроса, которому оно нужно. Поэтому каждый рантайм отправляет запросы через собственный клиент.
Рантайм брокера использует клиент, созданный при подключении. Поток выполнения обработчика со
своим рантаймом создаёт клиент при первом запросе, из той же конфигурации и того же кэша учётных
данных. Поэтому занятый поток выполнения никогда не задерживает соединения брокера.

Политика [`KinesisPublish`](api:ruststream_kinesis::KinesisPublish) вместе с соединением
конструирует издателя [`KinesisPublisher`](api:ruststream_kinesis::KinesisPublisher), который
пишет каждую запись одним вызовом `PutRecord`. Издатель принимает буфер, в который закодировано
ответное сообщение, и запись без заголовков - это сам буфер без изменений. Копия для повтора
возвращается в поток, который читает подписка, как показывает страница
[Завершение](settlement.md).

## Транспорт внутри процесса {/* #in-process-transport */}

С фичей `testing` тест подключает брокер внутри процесса. Тогда подключённый брокер, его подписки,
издатели и доставки работают с журналом, который хранится в тесте. Сборка без этой фичи не
содержит от него никаких следов: компилятор проверяет, что соединение, поток доставок, дескриптор
перемотки и завершение в точности равны по размеру своим формам для настоящего сервиса.

Журнал пишет запись так же, как издатель пишет её в Kinesis, с тем же ключом сегмента и тем же
конвертом, и читает её обратно тем же декодированием. Он отвергает то, что отвергает Kinesis, с
той же ошибкой, что и настоящий вызов: недопустимое имя потока, недопустимый ключ сегмента,
слишком большую запись и любой дескриптор, использованный после завершения работы. Он моделирует
позиции и перемотку, заголовки доставки, копии для повтора и поток мёртвых писем, а на возврат в
очередь отвечает `AckError::Unsupported`.

Часть поведения есть только у настоящего сервиса. Внутри процесса у потока один сегмент, поэтому
все записи упорядочены друг относительно друга. Аренд, контрольных точек, срока хранения и
изменения числа сегментов нет, и запись, оставшаяся необработанной, не возвращается. Любой поток,
который называет сервис, существует, а подписка открывается с конца потока.

Как части запускаются и останавливаются, показывает страница [Жизненный цикл](lifecycle.md), а
путь одной записи - страница [Путь](path.md).
