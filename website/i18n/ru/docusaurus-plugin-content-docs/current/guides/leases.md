# Несколько экземпляров

Это руководство запускает несколько экземпляров одного сервиса на одном потоке с таблицей аренд в DynamoDB, которая отдаёт каждый сегмент одному экземпляру и хранит его контрольную точку.

Kinesis не решает, какой потребитель читает какой сегмент.
Kinesis Client Library для других языков ведёт для этого [таблицу аренд](https://docs.aws.amazon.com/streams/latest/dev/shared-throughput-kcl-consumers.html), по строке на сегмент с его владельцем и контрольной точкой.
`ruststream-kinesis` ведёт такую же таблицу через [хранилище аренд](../components/leases/index.md).

## Один экземпляр {/* #one-instance */}

Брокер, у которого не задано хранилище, хранит аренды и контрольные точки в [`MemoryLeaseStore`](../components/leases/memory-lease-store.md), в памяти процесса.
Для одного экземпляра этого достаточно.
Два экземпляра на нём не знают друг о друге, поэтому каждый читает все сегменты и каждая запись обрабатывается дважды.
Перезапущенный экземпляр стартует с пустым хранилищем и открывает каждый сегмент с конца, если `start_at` не задаёт другую позицию.

## Таблица аренд {/* #the-lease-table */}

```toml title="Cargo.toml"
[dependencies]
ruststream-kinesis = { version = "0.7", features = ["dynamodb-lease"] }
aws-config = "1"
tokio = { version = "1", features = ["macros", "rt-multi-thread"] }
```

Фича `dynamodb-lease` добавляет [`DynamoLeaseStore`](../components/leases/dynamo-lease-store.md).
У его таблицы один строковый ключ раздела DynamoDB, `lease_key`, и больше ничего. Ей подходит оплата по запросам.
Таблица - часть инфраструктуры, как и поток: создайте её один раз через Terraform, CloudFormation или AWS CLI.
На локальном стенде добавьте `dynamodb` в `SERVICES` в файле compose и создайте таблицу там:

```bash
aws dynamodb create-table --table-name warehouse-leases \
  --attribute-definitions AttributeName=lease_key,AttributeType=S \
  --key-schema AttributeName=lease_key,KeyType=HASH \
  --billing-mode PAY_PER_REQUEST
```

Одна таблица обслуживает все потоки сервиса: строка хранит один сегмент одного потока под ключом `stream:shard`.

Хранилище и брокер получают одну конфигурацию AWS, поэтому оба обращаются к одному аккаунту и региону.
`aws_config::defaults(..).load()` читает её из окружения и выполняется асинхронно, поэтому `main` загружает её до того, как строит приложение и запускает его через `run`.
[`KinesisBroker::from_config`](../components/broker/credentials.md) принимает конфигурацию, а [`lease_store`](api:ruststream_kinesis::KinesisBroker::lease_store) - хранилище.
Запустите две копии сервиса с одинаковым окружением, и они разделят между собой сегменты `warehouse-orders`.

## Как экземпляры делят сегменты {/* #how-the-shards-are-shared */}

Каждый экземпляр перечисляет сегменты, когда открывается его подписка, и затем каждые десять секунд.
Он берёт аренду каждого сегмента, у которого нет владельца или аренда которого истекла, и читает эти сегменты.
Аренда действует десять секунд, и её владелец продлевает её каждые три.
Каждая запись в таблицу условная, поэтому два экземпляра никогда не держат один сегмент одновременно, а контрольная точка записывается, только пока её автор держит аренду.

Экземпляры не распределяют сегменты поровну: тот, кто перечислил сегменты первым, берёт все свободные.
Остальные берут сегмент, когда его владелец останавливается и освобождает свои аренды или когда его аренда истекает, потому что владелец аварийно завершился или потерял связь с сетью.
Экземпляр, у которого не удалось продление, сразу перестаёт читать этот сегмент и не записывает контрольную точку.

## Что читается заново при передаче сегмента {/* #what-a-handover-reads-again */}

Экземпляр, который забирает сегмент, продолжает после контрольной точки, записанной прежним владельцем.
Записи, которые прежний владелец обработал после своей последней контрольной точки, доставляются заново, как и [задержанная](checkpoints.md) им запись и всё, что за ней.
Если прежний владелец читал сегмент, но не записал ни одной контрольной точки, новый продолжает с первой прочитанной им записи.
Её хранит столбец `opened_at` строки сегмента.
Поэтому при передаче сегмента заново доставляется всё, что прежний владелец прочитал и не подтвердил, и ничего не пропускается, какую бы позицию ни задавал `start_at`.
Перезапущенный экземпляр продолжает так же, потому что контрольные точки хранятся в таблице.

## Имя каждого экземпляра {/* #naming-each-instance */}

Каждый брокер получает собственный идентификатор владельца, уникальный для этого экземпляра брокера, и таблица показывает его в столбце `lease_owner`.
[`owner_id`](../components/leases/owner-id.md) задаёт экземпляру имя, например по имени его пода.
Экземпляр, который перезапускается под тем же именем, сразу получает свои аренды обратно и не ждёт, пока они истекут.
Одно фиксированное имя нельзя давать двум экземплярам, которые работают одновременно: оба будут держать одни и те же сегменты и читать их.

## Обновление таблицы и другие хранилища {/* #upgrading-a-table-and-other-stores */}

Таблица, записанная прежней версией крейта, хранит строки под ключом из одного идентификатора сегмента.
[`legacy_stream`](../components/leases/legacy-stream.md) называет поток, которому принадлежат эти строки, и обновлённый сервис продолжает с них.
Хранилище на другой базе данных реализует [`LeaseStore`](api:ruststream_kinesis::LeaseStore): шесть вызовов, которые берут, продлевают, записывают контрольную точку, запоминают, где открылось чтение, читают и освобождают аренду.

## Тестирование {/* #testing */}

Первый тест запускает приложение внутри процесса с конфигурацией, построенной без ввода-вывода.
[Kinesis внутри процесса](../components/testing/index.md) не обращается к хранилищу аренд, поэтому тест проверяет обработчик.
Второй тест работает на стенде: он запускает два экземпляра на одной новой таблице, останавливает первый и видит, как второй забирает сегмент после контрольной точки первого.

```bash
KINESIS_TEST_ENDPOINT=http://localhost:4566 cargo test -- --test-threads=1
```

Живые тесты таблицы аренд самого крейта находятся в `tests/leases_kinesis.rs`.
